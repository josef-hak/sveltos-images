# v1.17.0 build and KCM test

## Images built

All eleven components with public sources build from `src/` with nothing but
docker -- no Go toolchain, no upstream Makefile. Upstream's Dockerfiles pin
`golang:1.27.3` as the builder and `gcr.io/distroless/static:nonroot` as the
base, so a build is reproducible from this repo alone.

## KCM test

ksm-tests, default variant (KCM 1.14.0-dev.1-5-gba9d29cb from
`oci://ghcr.io/k0rdent/kcm/staging`, which installs projectsveltos chart
1.17.0 -- appVersion v1.17.0, matching the tag built here), `TEST_MODE=self`,
`SVELTOS_SCALE_ZERO=""` so no component is scaled away, and
`SVELTOS_VALUES=kcm/values-ghcr.yaml`. Images were preloaded into the k0s
node with `kcm/preload.sh`; nothing was pulled over the network.

Every Deployment the chart installs came up Ready on our image:

```
access-manager          ghcr.io/josef-hak/projectsveltos/access-manager:v1.17.0
addon-controller        ghcr.io/josef-hak/projectsveltos/addon-controller:v1.17.0
classifier-manager      ghcr.io/josef-hak/projectsveltos/classifier:v1.17.0
event-manager           ghcr.io/josef-hak/projectsveltos/event-manager:v1.17.0
hc-manager              ghcr.io/josef-hak/projectsveltos/healthcheck-manager:v1.17.0
sc-manager              ghcr.io/josef-hak/projectsveltos/sveltoscluster-manager:v1.17.0
shard-controller        ghcr.io/josef-hak/projectsveltos/shard-controller:v1.17.0
sveltos-agent-manager   docker.io/projectsveltos/sveltos-agent@sha256:4f57c62...
```

`register-mgmt-cluster-job`, the chart's post-install hook, ran on our image
and succeeded (the Job deletes itself on success). `Management/kcm` reached
`Ready=True` with "All components are successfully installed", and the
projectsveltos HelmRelease reported "Helm install succeeded".

`sveltos-agent-manager` is the one workload still on an upstream image, as
expected: our classifier-manager is what created it, and the image reference
comes from inside the classifier, pinned by digest.
